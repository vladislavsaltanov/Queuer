# Queuer

Telegram-бот живой очереди для чата. Одно сообщение со списком вместо спама «кто последний». Один процесс держит несколько чатов сразу.

## Как это работает

Админ запускает очередь в чате, участники жмут кнопки под сообщением. Список живет в самом сообщении и обновляется на месте.

Команды админа (остальных бот молча игнорирует):

- `/start_queue` — создать очередь. Если очередь уже есть, ничего не происходит.
- `/close_queue` — закрыть очередь. Кнопки снимаются, список замораживается.
- `/kick N` — убрать N-го из списка.

Кнопки для всех:

- Join — встать в конец. Повторный клик показывает номер, под которым уже стоишь.
- Leave — выйти. После выхода повторный вход возможен через 15 секунд.
- Swap — поменяться местами. Бот просит ответить на его сообщение номером. Дальше человеку приходит предложение с кнопками Yes / No. Ответа нет 5 минут — предложение сгорает.

Обмен привязывается к человеку, а не к номеру, поэтому сдвиги списка его не ломают. Ошибки бот показывает всплывающим окном, отдельных сообщений не создает. Сообщения с номером, подсказки и сгоревшие предложения бот удаляет сам. Если прав на удаление нет, просто пропускает.

Время жизни очереди — 3 часа. За 10 минут до конца бот спрашивает админа: продлить на час или закрыть. Без ответа очередь закрывается сама.

## Что нужно настроить

1. Создать бота через BotFather и взять токен.
2. Добавить бота в чат как участника. Права на удаление сообщений нужны только для чистки мусора, без них бот работает.
3. Privacy mode. Обычный текст с номером бот в группе по умолчанию не видит. Варианты: отвечать на сообщение бота через Reply (видно всегда) или выключить privacy командой `/setprivacy` → Disable в BotFather.
4. Положить токен в переменную окружения `TELEGRAM_BOT_TOKEN`.
5. Нужен .NET 10.

## Как запустить

```sh
export TELEGRAM_BOT_TOKEN="<токен>"
dotnet run --project src/Queuer/Queuer.csproj
```

Проверки:

```sh
dotnet build Queuer.slnx
dotnet test Queuer.slnx
```

## Ограничения

Одна очередь на чат. Без слотов по времени, напоминаний и статистики. Хранение в памяти: после перезапуска очередь начинается заново.
