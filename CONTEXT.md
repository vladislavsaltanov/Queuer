# Queuer — живая очередь в Telegram

Одно сообщение — источник правды. Один токен, один процесс, N чатов.
Подробности потребительского правила — `docs/agents/domain.md`, трекер — `docs/agents/issue-tracker.md`.

## Глоссарий (использовать эти термины)

- **Очередь** — одна активная на чат (`chat_id → QueueState`).
- **Список** — `List<User>` внутри сообщения очереди, позиции 1-based.
- **Промпт** — вопрос «с кем меняешься», живёт 60с, удаляется вместе с ответом.
- **Оффер** — swap-сообщение с упоминанием цели, кнопки Да/Нет, TTL 5 мин.
- **Варнинг** — «До закрытия 10 мин», кнопки [+1 час] [Закрыть].
- **Закрыта** — `⛔ Очередь закрыта`, кнопки сняты, таймеры стоп.

## Решения (почему так)

- Polling `GetUpdates`, не webhook — один инстанс без входящего HTTPS (см. `docs/adr/0001-polling.md`).
- `msgId` уникален только внутри чата — все edit/delete парой `chat_id + msg_id`.
- Swap резолвится в `user_id` сразу — сдвиги номеров оффер не ломают.
- Ошибки только через `AnswerCallbackQuery(alert)` — чат не засоряем.
- Нет прав на delete — пропускаем, не падаем.

## Что НЕ делаем

Слоты по времени, напоминания, `/next`, несколько очередей на чат, веб-админка, статистика.
